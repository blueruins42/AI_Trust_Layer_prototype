核心问题

技术完美的系统，在用户侧却失败了

来源不透明

用户不知道答案来自哪份文档，无法验证。

置信度不透明

所有答案以同样的确定性呈现。

术语障碍

工程术语让非技术用户无法理解。

信任校准缺失

系统不告诉用户何时该自行核实。

五条设计原则

来自 PRD Step 3，指导所有设计决策

P1

Progressive Disclosure

默认最小化：只显示答案 + 置信度标签；来源、术语、验证建议按需展开。低置信度是唯一的主动提示例外。

P2

Calibration, Not Replacement

高置信度可直接使用，中置信度建议核对，低置信度仅供参考。系统提供决策依据，但不替用户决定。

P3

Plain Language First

术语解释默认显示大白话，正式定义点击展开。所有面向用户的文案通过「38 岁投标专员可读性」测试。

P4

Structured Data Contract

前后端通过 JSON Schema 通信，answer/sources/jargon/verification/metadata 按字段渲染，无需 NLP 解析。

P5

Human-AI Co-evolution Loop

前端帮助用户用好 AI，后端 Admin Dashboard 让管理员看到「信任健康度」，持续优化 RAG 数据库和术语库。每一次「验证点击」都是系统改进的信号。

MVP 功能

原型已实现 PRD Step 2 优先级矩阵中的 P0/P1 核心功能

F1

来源标注

文档名、页码、匹配度、原文摘录，按需展开。
F2

置信度指示 + 低置信警告

高/中/低三级标签，低置信度弹出非忽略警告横幅。
F3

术语解释层

答案中的术语高亮，大白话优先，正式定义可展开。
F4

验证建议 + 动作链接

标记需人工核对字段，一键跳转原文档页。
F7

管理后台

Trust Health、低置信触发率、高频术语 Top 5。
DC / N1 / N2

数据契约 + 延迟 + 校验

JSON Schema、渐进加载 ≤3s、Pydantic 校验降级。
