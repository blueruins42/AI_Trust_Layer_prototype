The Core Problem

Technically perfect systems fail at the user layer

Opaque Sources

Users can't verify which document an answer came from.

Opaque Confidence

All answers are presented with the same certainty.

Jargon Barrier

Engineering jargon blocks non-technical users.

No Trust Calibration

The system never tells users when to verify.

Five Design Principles

From PRD Step 3 — guiding every design decision

P1

Progressive Disclosure

Minimum by default: only the answer + confidence label; sources, jargon and verification expand on demand. Low-confidence is the only proactive-alert exception.

P2

Calibration, Not Replacement

High → safe to use, Medium → verify, Low → reference only. The system provides decision support — never decides for the user.

P3

Plain Language First

Jargon explanations default to plain language; formal definitions expand on click. All user-facing copy passes the "38-year-old bid specialist" readability test.

P4

Structured Data Contract

Frontend and backend communicate via JSON Schema — answer / sources / jargon / verification / metadata are rendered by field, no NLP parsing.

P5

Human-AI Co-evolution Loop

The frontend helps users get the most from AI; the Admin Dashboard gives administrators visibility into "trust health," continuously improving the RAG corpus and jargon library. Every verification click is a signal for system improvement.
